  For the failure-mode requirement (Step 9), the test period was scanned for the day with the

====================================================================================================
STEP 2 -- FORECAST ISSUE TIME
====================================================================================================
  For each event, T is set to EXACTLY 24 hours before that day's actual peak timestamp. This is
  the maximum legitimate horizon the locked pipeline supports (by construction, every feature is
  built from information at or before target-24h) -- so each replay demonstrates the full,
  genuine 24-hour-ahead capability rather than a shorter, easier-to-hit window. The choice was
  fixed by this rule BEFORE inspecting how well the forecast performed.

====================================================================================================
STEP 3 -- WEATHER FORECAST VINTAGE
====================================================================================================
  Both replays use temp_corr: the genuine day-1-lead forecast temperature (Open-Meteo Previous
  Runs API, validated in Phase 4) plus the adaptive 30-day time-of-day bias correction validated
  in Phase 5. No observed/reanalysis or hindsight weather value is used anywhere in either replay.

## 11. Failure/success analysis
====================================================================================================
  PRIMARY (2025-06-12): PARTIAL SUCCESS.
    - The point forecast undershot the actual peak by 597.4 MW (-7.1%) -- the point forecast alone would have understated the event.
    - The uncertainty band DID capture it: actual 8,392.6 MW was inside the
      P10-P90 band, 25.0 MW below P90 -- so a dispatcher who
      read the FULL band, not just the point forecast, would not have been surprised.
    - The stress score reached 64.9 (WATCH), 24.0 hours ahead of the actual peak -- correctly elevated above ordinary days (see Phase 8 Section 3),
      but did NOT cross into HIGH (75) even though the actual event reached 93% of assumed capacity. This is the same
      understatement identified and only partially narrowed in Phase 8 -- shown here again, live,
      in a genuine forward replay rather than retrospective analysis. It is not hidden.

  SECONDARY (2025-06-11): GENUINE FAILURE.
    - The point forecast undershot the actual peak by 809.4 MW (-9.9%), and the actual peak was OUTSIDE the P10-P90 band (P90 margin -246.8 MW -- i.e. the band did not reach the actual).
    - WHY: reliability was already flagged LOW at issue time T, for a stated, verifiable reason:
        - critical 24h demand input reconstructed from the nearest available earlier day for 35 of 92 blocks in this 24h window (telemetry gap)
        - previous-24h demand telemetry only 64% complete at worst
    - The system did not hide this: it told the operator, 24.0 hours in
      advance, that its own strongest input was reconstructed rather than observed, and its
      stress score (61.7, WATCH) and peak risk (MODERATE) were both already elevated above an ordinary day. What it could NOT do was
      correct the magnitude of the point forecast or widen the band enough to actually contain
      the surprise -- this matches the Phase 7 finding that LOW-reliability coverage (was 51.3%,
      59.0% after reliability-aware widening) remains well short of the 80% nominal target.
    - This is presented as a genuine, uncorrected miss, exactly as it happened.
